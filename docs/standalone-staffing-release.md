# Event Host: standalone staffing release

This release is independent of Staff Tools and ShiftFlow. It adds the 7shifts-based team editor, home-card staffing alerts, and Kitchen and Checklist suggestions. It does not include a Staff Tools route, employee sign-in change, credential, or new scheduled job. With `EVENT_HOST_PUBLIC_STAFFING_ENABLED=true`, anyone with the Event Host URL can view published employee names and save event teams without a password. The owner explicitly approved this public operational access. Admin actions still require the existing separate Admin credential; public staffing does not unlock Admin, change policy, or run a persisted sync. VIP cards still say **Shift Lead**.

## Assigning staff on a selected future date

The home-card **Assign Staff** button opens the event's multi-select roster directly inside that card, without an Admin session or password. It lists all-role published shifts on that event's day, not a guessed static employee list. A fresh saved schedule is reused; otherwise a read-only provider check verifies the seven days starting on the selected date, including overnight boundary metadata. It uses the existing Tripleseat access token without refreshing or reconnecting. Failed verification shows a retry message, never unverified choices.

Opening the dropdown performs no database writes and does not update automatic matches. The server returns a short-lived encrypted review token bound to the exact event, date, saved version and original schedule observation. **Save staffing team** applies only the clicked team and explicitly confirmed shift moves, in one version-checked write. Unrelated assignment rows are retained. Expired reviews, stale versions, conflicting assignments and cross-origin writes are rejected. Admin-only sync and policy endpoints remain protected. This public access is intentional, not employee authentication.

Only one schedule week is verified at a time. Switching weeks retains manual teams and unresolved alerts outside that week, but does not verify their coverage or allow their old data to prefill operational forms. Verify the other week again before editing its teams. Freshness uses the actual observation time, expires after 45 minutes or an Eastern calendar-day change, and is never extended by saving an assignment.

Saved manual team names remain visible on the dashboard for the exact, unique saved event and date even when schedule verification expires. The card explicitly says **Saved assignment · schedule verification needed** and retains its review action. This does not verify current availability, expose stale automatic matches, allow an unverified edit, or prefill an operational form from stale data.

This date-selection change uses the existing versioned staffing document; it requires no new database migration. Preserve the configured owner-approved Admin credential and keep Staff Tools sign-in and handoff off during this release.

## Rollback

Restore the previous known-good deployment (or turn off `EVENT_HOST_PUBLIC_STAFFING_ENABLED` and redeploy to disable passwordless assignment). Confirm the previous Admin and staff behavior and keep the standalone staffing rows intact for review. Do not drop databases, replay unrelated migrations, reuse staging credentials, or change any Staff Tools or ShiftFlow settings.
